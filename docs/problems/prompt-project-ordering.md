# 问题记录

## ISSUE-003 拖拽相邻下移无效且保存后可能跳回第一页

**优先级**: Medium
**来源**: Review

### 1. 现象
自审拖拽链路发现两处边界缺陷：向下拖到紧邻的下一项时顺序可能不变；保存后的列表刷新会把分页重置到第一页，打断连续整理。

### 2. 细节
- **复现步骤**:
  1. 手动模式下将条目向下拖到紧邻目标，或在非第一页完成拖拽；
  2. 前者不产生预期移动，后者在数据刷新后跳页。
- **环境/上下文**: 聊天词库面板；原生 HTML5 拖拽；`pl:data-changed` 会同时刷新提示词和项目对象。

### 3. 根因
初版插入位置未区分拖拽方向，删除源条目后目标索引发生变化。分页 effect 同时依赖完整列表和项目对象，将普通数据刷新误判为筛选条件变化。

### 4. 解决方案
- **短期修复（源码已修改，待回归）**: 向下移动落在目标后、向上移动落在目标前；筛选变化时重置页码，总页数变化时仅校正越界，项目依赖使用稳定的 `currentProject?.key`。
- **长期优化**: 为相邻上下移动、筛选隐藏项、跨页保存及同项目对象刷新补充纯函数与组件测试。

### 5. 经验教训
拖拽算法必须基于删除源条目后的索引计算；派生数据刷新与用户主动切换筛选应使用不同的状态重置路径。

## ISSUE-004 项目路径与新建归属可能误归类

**优先级**: High
**来源**: Review

### 1. 现象
自审项目归属链路发现：相对路径可能按插件进程工作目录解析；在指定项目筛选下新建提示词时，初版仍可能默认关联当前会话项目；快速切换会话时，旧项目查询可能后返回并覆盖新会话项目。

### 2. 细节
- **复现步骤**:
  1. 在数据管理中输入相对项目路径，选择非当前项目的指定项目筛选后新建，或快速切换两个会话；
  2. 初版可能生成错误项目 key、把新提示词归到当前项目，或短暂沿用上一个会话的项目。
- **环境/上下文**: Windows/POSIX 路径规范化；数据管理支持手动重新关联项目路径。

### 3. 根因
路径解析缺少绝对路径约束；新建表单的默认项目只考虑当前会话，没有优先采用用户正在查看的指定项目；项目查询未绑定请求版本与会话身份，异步响应可能乱序覆盖。

### 4. 解决方案
- **短期修复（源码已修改，待回归）**: 强制项目路径为绝对路径，统一尾部分隔符与 Windows 匹配键；指定项目筛选下优先归属该项目；项目查询仅接受最后请求，并将结果与 `sessionId` 绑定。
- **长期优化**: 增加 Windows 大小写、根目录、尾部分隔符、非法相对路径、指定项目新建及会话切换乱序响应的自动化测试。

### 5. 经验教训
项目隔离必须先在数据边界保证归属准确，再做界面过滤；用户的显式筛选上下文优先于环境推断。

## ISSUE-005 排序模式恢复与保存失败反馈不完整

**优先级**: Medium
**来源**: Review

### 1. 现象
初版从手动切回智能排序时可能仍沿用当前数组顺序；拖拽保存失败时，部分入口只回滚列表而未明确显示失败原因。

### 2. 细节
- **复现步骤**:
  1. 手动拖拽后切回智能排序，观察是否立即恢复新鲜度、使用频率和更新时间规则；
  2. 模拟顺序保存接口失败，观察聊天面板是否提示。
- **环境/上下文**: 智能排序由宿主列表顺序与前端派生顺序共同影响；拖拽采用乐观更新。

### 3. 根因
模式切换仅改变标志位，没有按智能规则重算；错误状态只覆盖部分视图，回滚与错误提示未形成统一链路。

### 4. 解决方案
- **短期修复（源码已修改，待回归）**: 前端按宿主同一规则重算智能顺序；聊天面板与数据管理均在保存失败时回滚并展示错误。
- **长期优化**: 统一排序规则与拖拽保存状态管理，补充模式切换、接口失败和并发新增条目的测试。

### 5. 经验教训
乐观更新必须同时提供可靠回滚和可见错误；派生排序不能依赖接口返回数组恰好处于目标顺序。
